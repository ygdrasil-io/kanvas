# W6 Final Gates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Corriger le témoin public RRect, puis rendre la réservation logique des artefacts natifs opaques exhaustive et authentifiée avant matérialisation sur la route W6 admise.

**Architecture:** `:gpu-plan` fige un inventaire par owner et slot avant le budget et la publication du graphe ; `:gpu-renderer` ne peut consommer que cet inventaire. Les ressources physiques `PlanResource`, les bundles programmes et les samplers ont des charges distinctes ; les leases W6d existants ne sont jamais comptés deux fois. Les pixels et les frontières B/B−1 restent observés par les seules API publiques.

**Tech Stack:** Kotlin, Gradle/JUnit 5, `:math`, `:render-ir`, `:gpu-plan`, `:gpu-renderer`, `:kanvas`, WebGPU.

**Spec:** `refactor/specs/2026-09-26-w6-final-gates-design.md` (et `refactor/specs/2026-09-16-w6-layers-effects-design.md`, §§8, 11, 17.8–18).

## Global Constraints

- Base : `codex/w6e-effects-convergence` / Draft PR #2408 ; nouvelle Draft PR stackée, sans merge automatique.
- Ordre W6 §8 : couverture → mask filter → source → image filter → clip terminal → blend.
- Program bundle : `max(4096L, checked descriptor bytes + checked recipe bytes)` octets logiques ; sampler W6 : `4096L` par slot ; sampler résident W5h : `4096L` par entrée. Ce ne sont pas des bytes driver.
- Owner opaque : `PlanPassId` + ordinal stable pour chaque bundle, `PlanResourceId` pour le sampler ; génération device, descriptor/recipe canonique, slot et lifetime jusqu'à completion/quarantine.
- Pic en checked-I64, sans rabais de cache ni aliasing non prouvé ; B admet, B−1 refuse avant matérialisation W6, sans sibling, puis `discardRecordedOperations()` permet la récupération sur la même `Surface`.
- Géométrie et calculs géométriques uniquement dans `:math`, nomenclature I/F32/64 ; aucun bounds, pass, resource, ID, cache-key ou fallback legacy ajouté par le renderer après freeze.
- Témoins publics seulement (`Surface`, `Picture`, paint/layer/filter, diagnostics, `render()`, `readPixels`, `discardRecordedOperations()`), attentes et B avant `Surface`/`PictureRecorder`, positifs avec scopes `Render` + `Readback` ; pas de fake device, hook, reflection, compteur privé ou test statique d'infrastructure.
- Hors périmètre : fonts/glyphes, codecs/formats externes, GMs/dashboard/renders/scores/rebaseline, suite Skia globale, `jpg-color-cube`, SkSL/WGSL arbitraire, F16/HDR positif, device-loss non observable, retrait legacy W8.
- Exit natif 133/134 : `UNKNOWN`, jamais PASS ; conserver séparément commande, exit Gradle, XML JUnit (F/E/S), exit natif et commit source.
- Terra implémente séquentiellement ; Sol relit chaque tâche puis la branche entière ; Astra seulement si un blocage architectural/numérique est démontré.

## Review Focus

1. Un RRect AA coupé par un clip dur : le flou doit exister avant le clip, et aucun pixel hors clip ne doit survivre — Task 1, `clipped rounded rect mask blur preserves its frozen analytic coverage`.
2. Un `FilterCoverageSourcePass` stencil à deux packets ou un `RenderPass` à plusieurs draws : chaque bundle doit recevoir un ordinal distinct — Task 2, `multipleNativeBundlesOfOnePassRetainIndependentBudget`.
3. Deux passes W6d de même recette, ou un cache chaud : l'égalité du descriptor ne doit ni fusionner les owners ni diminuer B — Tasks 2 et 4, `equalProgramsKeepTwoLeases` et `warmCacheRemainsPessimisticAtExactBudgetBoundary`.
4. Une ancienne génération ou un cache en éviction/quarantine : aucune lease ne doit redevenir valide ni être relâchée avant completion — Task 3 si le sampler positif est admis, sinon Task 4 note le gap ; audit Sol des chemins hit/miss/eviction/retirement (pas de claim de hit public).
5. Un sampler demandé sans effet enregistré qui le déclare : la voie publique doit refuser, pas fabriquer un témoin positif — Task 3, préservation `extraResourceKindsAreRefused` ; la frontière positive sampler est un gate de décision explicite ci-dessous.

## Décision de preuve à confirmer avant Task 3

Le catalogue public contient seulement `kanvas.runtime.child-opacity` et `kanvas.runtime.image-opacity`, tous deux avec `logicalResources.isEmpty()`. `PlanCacheResourceRequest.Sampler` et `GPUW5hRuntimeResourceSessionCache` savent gérer un sampler, mais aucun effet enregistré positif n'en demande un ; `W5hRuntimeEffectCatalogTest.extraResourceKindsAreRefused` confirme le refus public. La matrice positive « sampler runtime consommé par W6, B/B−1 » de la spec est donc **non exécutable avec l'API admise actuelle**. Ne pas contourner cela par un test d'infrastructure ou un effet WGSL legacy. Deux décisions recevables lors de la revue de ce plan : (A) autoriser une spec distincte pour un effet enregistré minimal à sampler et sa preuve publique, puis l'empiler avant de clore W6 ; (B) reporter le sampler positif **et son changement de comptabilité non testable**, tout en livrant les gates RRect/programmes et en laissant W6 ouvert. Ce plan recommande **B** pour ne pas transformer une correction de comptabilité en nouvelle sémantique de runtime effect. Sans décision, Task 3 s'arrête au gate et aucune clôture W6 n'est déclarée.
